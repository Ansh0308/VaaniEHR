# Data inventory (Phase 12B Run 2, ADR-D45)

What data VaaniEHR holds, why, where, who can read it, how long it stays, and whether it leaves the system. Field **names** only, never values. The test `apps/api-node/test/data-inventory.db.test.ts` fails when a database table is added without a row in section 2, or a row names a table that does not exist.

> **Legal bases and retention periods are marked "to be checked by my guide / institution".** This file records what the software does today. It does not decide what the law requires (for example the Digital Personal Data Protection Act, 2023, or medical-record rules). The data in this project is **simulated or acted** (SIMULATED_DATA_ONLY); the inventory describes how it would be handled if it were real.

Roles: **doctor** (the session's own doctor), **staff**, **admin**, **researcher** (anonymised audit only), **service** (the speech service, signed requests only), **owner-role** (database owner: migrations and tests, not the running app).

## 3. What leaves the system, and under what consent

| Destination                    | What is sent                                       | Only when                                                                          | Consent or rule                                   | Where enforced                                                 |
| ------------------------------ | -------------------------------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------- | -------------------------------------------------------------- |
| Sarvam (speech to text)        | audio of the **owner's own voice**                 | the paid engine is chosen, a cap allows it, the recording is on the own-voice list | consent `audio` + `ai_processing`; own-voice rule | `apps/asr-py/app/own_voice.py`, `usage.py`, `consent.py`       |
| LLM provider (fact extraction) | transcript text declared **simulated**             | `LLM_PROVIDER` is set, `--yes-run` or the opt-in, caps allow                       | consent `ai_processing`; simulated-text rule      | `apps/asr-py/app/simulated_text.py`, `extraction/llm_usage.py` |
| WhatsApp Cloud API             | the approved Gujarati summary (template variables) | real sending is switched on, the number is on the test allowlist                   | consent `whatsapp`; doctor approval; signed visit | `apps/api-node/src/whatsapp/`                                  |
| ABDM sandbox                   | a sandbox TEST identity and OTP, RSA-encrypted     | `ABDM_PROVIDER=sandbox`, the flag and credentials are set                          | staff attestation; identity guard                 | `apps/api-node/src/abdm/`                                      |
| HL7 FHIR validator             | the FHIR bundle JSON                               | `FHIR_VALIDATOR_URL` is set; it is a **local container**                           | none leaves the machine                           | `apps/api-node/src/fhir/validator.ts`                          |

Legal bases for each of these: **to be checked by my guide / institution**.

## 4. Open items this inventory depends on

- Retention for clinical data other than audio is not defined (only the 90-day audio rule exists, PRD NFR-PRIV-01 [Assumption]). Owner decision with the guide / institution.
- Whether a signed record must be kept after an erasure request: OCI-016 (open).
- Breach notification, data-processor agreements with Sarvam, the LLM provider and Meta: OWNER_ACTIONS.
